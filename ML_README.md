# CyberLens AI — Machine Learning Threat Detection Module

## 1. Overview & ML Architecture
The **Threat Detection Module** in CyberLens AI provides automated, flow-based network intrusion detection. Rather than treating individual packets as isolated events, it reconstructs bidirectional 5-tuple network conversations (flows), computes statistical traffic features matching the **CIC-IDS2017** benchmark, and applies a trained **Random Forest Classifier** to classify flows as **Normal (0)** or **Malicious (1)** with real probability confidence.

### Architecture Flow:
```text
CIC-IDS2017 CSV Dataset
        ↓
Dataset Loader & Cleaning (ml/dataset/loader.py)
        ↓
Feature Selection & Target Encoding (BENIGN=0, Attacks=1)
        ↓
80/20 Stratified Train/Test Split
        ↓
Random Forest Classifier Training (ml/train_model.py)
        ↓
Evaluation & Metric Generation (ml/evaluate_model.py)
        ↓
Model Artifacts: random_forest.pkl + feature_columns.pkl
        ↓
PCAP Upload & Ingestion (app/routes/pcap.py)
        ↓
Scapy Bidirectional 5-Tuple Flow Grouping (ml/packet_features/feature_extractor.py)
        ↓
Statistical Flow Feature Transformation & Validation
        ↓
Inference Service (ml/predict.py) -> Normal/Malicious + Actual Model Confidence
        ↓
Database Persistence (AnalysisReport in SQLite)
        ↓
Flask REST API (/api/v1/cases/<id>/analysis)
        ↓
React Forensic Investigation UI (ThreatDetection & PacketAnalysis)
```

## 2. CIC-IDS2017 Dataset & Placement

The system trains on the **CIC-IDS2017** dataset (generated by the Canadian Institute for Cybersecurity).

### Dataset Placement:
Place any of the standard CIC-IDS2017 CSV files into:
```text
backend/ml/dataset/
├── Monday-WorkingHours.pcap_ISCX.csv
├── Tuesday-WorkingHours.pcap_ISCX.csv
├── Wednesday-workingHours.pcap_ISCX.csv
├── Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv
├── Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv
├── Friday-WorkingHours-Morning.pcap_ISCX.csv
├── Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv
└── Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv
```

The dataset loader automatically discovers and parses any CSV files present in `backend/ml/dataset/`.

## 3. Feature Schema (10 Baseline Flow Features)

The model relies on 10 flow-level statistical features that are accurately reconstructible from raw PCAPs using Scapy:

| # | Feature Name | Description | PCAP Extraction Logic |
|---|--------------|-------------|-----------------------|
| 1 | `Destination Port` | Transport layer port | Destination port from initiator packet |
| 2 | `Flow Duration` | Duration of communication | Difference between first and last packet timestamp (in $\mu s$) |
| 3 | `Total Fwd Packets` | Forward packet count | Count of packets from initiator to responder |
| 4 | `Total Backward Packets`| Backward packet count | Count of packets from responder to initiator |
| 5 | `Total Length of Fwd Packets` | Forward byte volume | Sum of packet lengths in forward direction |
| 6 | `Total Length of Bwd Packets` | Backward byte volume | Sum of packet lengths in backward direction |
| 7 | `Flow Bytes/s` | Traffic throughput | Total bytes / duration in seconds |
| 8 | `Flow Packets/s` | Packet throughput | Total packets / duration in seconds |
| 9 | `Packet Length Mean` | Average packet size | Mean packet length across all packets in the flow |
| 10 | `Packet Length Std` | Packet size variation | Standard deviation of packet lengths in the flow |

## 5. Training & Evaluation Commands

### Train Model:
```bash
cd backend
python ml/train_model.py
```
*Optional flags:*
- `--dataset-dir <path>`: Custom dataset directory.
- `--n-estimators 100`: Number of trees in the Random Forest (default: 100).
- `--max-rows 50000`: Read up to N rows per file for faster training iterations.

### Evaluate Model:
```bash
cd backend
python ml/evaluate_model.py
```
*Outputs generated:*
- `backend/ml/results/model_metrics.json`: Accuracy, Precision, Recall, F1, Confusion Matrix, Classification Report.
- `backend/ml/results/confusion_matrix.png`: High-resolution confusion matrix heatmap.

## 9. Encrypted Traffic & Forensic Integrity

- **No Payload Decryption**: The module does **not** attempt to break or decrypt TLS/HTTPS sessions.
- **Metadata-Driven**: Detection operates strictly on observable transport-layer headers, statistical behavior, packet timing, and flow-level characteristics.

---

## 10. Limitations & Troubleshooting

1. **Missing Model Error**:
   If the API returns `"ml_model_status": "no_model"`, train the model by placing CIC-IDS2017 CSV files in `backend/ml/dataset/` and executing `python ml/train_model.py`.
2. **Single Packet Flows**:
   Flows consisting of a single packet have a duration of 0.0 seconds; throughput metrics (`Flow Bytes/s`, `Flow Packets/s`) and standard deviations are safely clamped to 0.0 to prevent division by zero or NaN artifacts.
